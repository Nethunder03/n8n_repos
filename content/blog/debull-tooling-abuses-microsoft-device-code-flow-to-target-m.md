# DEBULL : Comment les cybercriminels contournent le MFA en abusant du flux Device-Code de Microsoft ![L'outil DEBULL abuse du flux 'Device-Code' de Microsoft pour cibler les comptes M365](https: La sécurisation des accès aux environnements d'entreprise est devenue une priorité absolue face à l'ingéniosité des cybercriminels. Récemment, une nouvelle menace a été mise en lumière par les chercheurs de ZeroBEC : l'utilisation d'une plateforme d'attaque baptisée **DEBULL**. Cet outil sophistiqué automatise des campagnes de **Device Code Phishing**, une technique d'usurpation d'identité particulièrement redoutable qui cible les comptes Microsoft 365 et Entra ID en détournant un mécanisme d'authentification tout à fait légitime pour contourner l'authentification multifacteur (MFA). --- ## Détails techniques : Le détournement du "Device Authorization Grant Flow" Contrairement aux attaques de phishing traditionnelles (notamment de type *Adversary-in-the-Middle* ou AitM) qui reposent sur la mise en place de fausses pages de connexion imitant l'identité de Microsoft, le **Device Code Phishing** ne nécessite aucune contrefaçon de site. Cette attaque abuse du flux d'autorisation d'appareil (**Device Authorization Grant Flow**), un protocole basé sur l'OAuth 2.0 conçu à l'origine par Microsoft pour faciliter la connexion sur des appareils aux interfaces de saisie limitées, comme les téléviseurs connectés, les consoles de jeux ou les imprimantes de bureau. Dans un scénario normal, l'appareil affiche un code court à l'utilisateur, l'invitant à se rendre sur un navigateur web tiers (sur un PC ou un smartphone) et à y saisir ce code afin de valider la session. Les attaquants exploitent cette séparation des terminaux pour s'immiscer au cœur de la validation. Le déroulement de l'attaque est le suivant : 1. **Génération du code** : L'attaquant initie en arrière-plan une demande légitime de connexion à Microsoft 365, générant ainsi un code de connexion éphémère. 2. **Envoi du leurre** : Ce code est envoyé à la victime via un e-mail ou un message Teams usurpant une invitation de collaboration ou le partage d'un document professionnel. 3. **Validation par l'utilisateur** : Trompée, la victime clique sur le lien officiel de Microsoft et y saisit le code fourni par l'attaquant. 4. **Prise de contrôle** : Une fois le code entré par l'utilisateur légitime, le courtier d'authentification de l'attaquant intercepte le jeton d'accès (token) d'authentification généré. L'attaquant est alors connecté au compte de la victime, sans avoir eu besoin de lui dérober son mot de passe et en ayant totalement contourné le MFA. L'utilisation de la plateforme **DEBULL** industrialise ce processus. Elle permet aux attaquants de générer et de sonder dynamiquement les jetons d'appareil de Microsoft en arrière-plan, rendant l'attaque rapide, flexible et difficilement détectable par les systèmes de sécurité standards. --- ## L'infrastructure DEBULL : Un modèle de Phishing-as-a-Service Selon les analyses de ZeroBEC, **DEBULL** se présente sous la forme d'un framework réutilisable s'apparentant à du **Phishing-as-a-Service (PhaaS)**. Il offre aux affiliés des capacités avancées de personnalisation : * **Personnalisation des leurres** : Les opérateurs peuvent modifier directement le code HTML, CSS et JavaScript pour adapter la page d'atterrissage aux cibles visées (thèmes de paiement, dossiers partagés, etc.). * **Post-exploitation intégrée** : DEBULL intègre un workflow dérivé du célèbre outil open source **GraphSpy**, optimisant l'accès et l'extraction post-compromission des données au sein des environnements Microsoft 365 et Entra ID. * **Origine des développeurs** : L'analyse du code source a révélé des marqueurs rédigés en langue turque, bien que cela ne suffise pas pour attribuer formellement l'attaque à un groupe de menace spécifique. Cette campagne partage de nombreuses similitudes de tactiques, techniques et procédures (TTP) avec le groupe d'acteurs de menace documenté par Microsoft en février 2025 sous le nom de **Storm-2372**. --- ## Quel est l'impact pour les organisations ? Une fois l'accès obtenu, les attaquants bénéficient d'un accès persistant à l'ensemble du tenant Microsoft 365 de l'utilisateur. Les conséquences potentielles sont dévastatrices : * **Piratage de messagerie en entreprise (BEC)** : Utilisation de la boîte mail légitime pour mener d'autres campagnes de phishing internes (techniques de saut de compte ou "ATO jumping"). * **Vol de données sensibles** : Accès aux fichiers SharePoint, OneDrive, et aux conversations Teams confidentielles. * **Mouvements latéraux** : Escalade de privilèges au sein du réseau d'entreprise. * **Déploiement de ransomwares** : Phase finale de sabotage suite à une infiltration réseau réussie. --- ## Recommandations : Comment se protéger ? Pour contrer l'abus du flux de code d'appareil, plusieurs mesures techniques doivent être déployées : 1. **Désactiver le Device Code Flow** : La mesure la plus efficace consiste à désactiver cette méthode d'authentification dans Microsoft Entra ID si votre entreprise n'utilise pas de terminaux contraignants (imprimantes sans écran, smart TV). 2. **Appliquer des politiques d'Accès Conditionnel** : Si le protocole doit être maintenu, créez des politiques d'accès conditionnel strictes pour restreindre son utilisation uniquement depuis des adresses IP d'entreprise fiables ou des appareils de confiance gérés. 3. **Sensibilisation accrue des utilisateurs** : Sensibilisez vos collaborateurs sur cette technique spécifique. Un utilisateur ne doit jamais saisir un code d'authentification reçu à la suite d'une invitation spontanée par e-mail ou messagerie instantanée. 4. **Surveillance des logs de connexion** : Configurez des alertes d'anomalie dans vos outils SIEM pour détecter les connexions réussies via le flux *Device Authorization Grant* provenant de localisations ou d'appareils inhabituels. --- ## Sources Source: The Hacker News - https:
